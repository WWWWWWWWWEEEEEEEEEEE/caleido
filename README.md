## 宗旨

不是"把任务拆给几个模型"，而是：

> **把全部难度集中到一个严格类型化的中间表示上，让每个模块都能被独立、低成本地训练和替换。**

由此三条推论：

- 接口只有一份，所以 trace 回放就能自动生成训练数据，数据集不要钱。
- 模块输入分布固定，所以每个模块都能单独评测、单独换模型。
- 中间表示一旦不完备，系统上限就锁死在那——**schema 的优先级高于任何一行代码**。

## 模块，不是 agent

这里的东西叫模块，不叫 agent。区别是：agent 自己决定调谁、用什么工具，输入分布是开着的；模块的拓扑固定、输入输出类型固定，输入分布才是闭的，才训得动。

所以两条硬规则，破了整个方案就散：

1. **只有 controller 能调用 coder。** 上游可以互相问，但改代码这件事只有一个入口。
2. **spec 只有一个写者：controller。** 一旦谁都能改 spec，coder 的输入分布就散了，训练和评测同时失效。

流转：

```
user → controller（核实边界 → 出 spec） → imager（发散路径） ⇄ investiganer（核实）
     → controller（定稿 spec，唯一写者） → coder → debugger（跑）
     → controller（收敛 / 重排 / 回问用户） → noter（存档）
```

## 六个模块

- **controller**：唯一跟人说话的东西。核实边界、把人类语言翻译成机器语言、维护 spec、派活、收敛循环。它自己不必是自研模型，可以直接接别人的大模型。
- **imager**：只负责发散，不出最终结果。在显式路径空间上搜索（任务 → 子目标 → 候选方案 → 风险点 → 依赖），给出几条可执行路径，交给 investiganer 和 controller。
- **investiganer**：把假设变成可判定的事实。查文档、翻代码、跑属性测试、造反例。结论只回给 imager 和 controller，不直接指挥 coder。它交付的是**反例**，不是可行性报告。
- **coder**：只干活。接口里不出现自然语言：输入是签名、类型、不变量、测试，输出是函数体。歧义不是它的责任，是 controller 的责任。
- **debugger**：先跑，再判。跑测试、跑 lint、解析 stderr——这部分是确定性的，**不要模型**。只有"这段报错意味着什么"才需要小模型。
- **noter**：不是模型。就是按 task_id 分文件的 `.md`，配检索。

失败信号必须分两类：一类是代码错，一类是 spec 错（自相矛盾 / 无法满足 / 藏了没声明的假设）。只当代码错处理，spec 有错时会把正确的代码越改越坏，而且永远收敛不了。改 spec 的权力只在 controller 手上。

## 通信

- **传输层**直接吃 agent-bus（`Y:\agent-bus`）：事件溯源、任务板、租约回收、MCP / CLI / HTTP 三条通道都已经跑通，不要再造。
- **内容层**是自己的类型化 spec：字段强约束、可校验。别用自由 JSON——自由 JSON 等于允许上游偷偷塞自然语言，协议立刻作废。
- 总线只能拉起本地进程，拉不起 GUI agent（agent-bus 第七节那条限制）。所以模块必须是能被 busd 装载 / 卸载的进程，"按需唤醒"才真正成立。

## 记忆：空间换性能

- **事实层**：agent-bus 的 `data\events.jsonl`。append-only，谁在什么时候收到什么，全在里面，用来回放和审计。
- **语义层**：caleido 自己的 `.md`，一个 task 一个文件，固定三节——spec / 试过的路（附失败原因）/ 结论。controller 醒来只读这一个文件就能接上，不用重跑上下文。
- 别把 `.md` 全量回灌 prompt。8GB 的上下文预算要留给 spec 和测试，历史按 task_id 捞相关段落。

## 异构接入

六个位置都不是非要自己训的模型，谁合适谁上：

- controller 可以直接接现成大模型。
- 联网查资料挂在 qoder 上，让云端 Qwen 帮 controller 核实——本机不承担这部分显存。
- coder 可以换成本地 7B，也可以换成云端模型，按任务难度路由。
- 换模块只是换一个进程，不影响别的模块。

这才是分体真正的收益：**每个位置能独立替换和升级，不用整体重训。**

## 8GB 2080 上怎么活

物理约束（估算，Qwen2.5 系列 Q4_K_M）：

| 位置 | 模型 | 显存 | 驻留方式 |
|---|---|---|---|
| 槽位 A（重） | 7B | 4.7GB 权重 + 约 0.9GB / 16k 上下文 | 按需装载 |
| 槽位 B（轻） | 1.5B | 约 1.1GB | 常驻 |
| controller | 3B 或占用槽位 A | 约 2.0GB | 常驻，或与 A 互斥 |
| noter / debugger（确定性部分） | 不用模型 | 0 | — |

三条结论：

1. 同一时刻只有一个重模块在跑——这是分体架构跟 8GB 天然匹配的地方。
2. **"controller 可以休眠"不是可选项，是唯一可行解。** 它休眠 = 把槽位 A 让给 coder。
3. 唤醒比生成便宜一个数量级：从盘加载 7B 约 2–5 秒，7B 生成 500 token 约 20–40 秒。所以该换就换，不要为了不换模型而牺牲质量。权重别放 Y 盘（看着像机械盘 / 网络盘），放 NVMe。

## 训练路线

现在不训。顺序不能反：

1. 手写 spec schema，拿 3 个真实小任务手工填通
2. 用现成模型扮演各模块，跑通 spec → code → 测试闭环
3. 攒 trace
4. 训 coder（监督，相对简单）
5. 最后才训 imager（RL，reward 来自下游是否跑通）

8GB 上 QLoRA 的现实边界：1.5B 舒服，3B 勉强，7B 不行。所以专才模块的目标定在 **1.5B–3B**，别惦记 7B。

空闲学习（controller / investiganer 上网自学）保留，但必须先定义"学什么"和"怎么验收"，否则一定跑偏。优先级排在闭环跑通之后。
